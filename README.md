# RP Stamina (`rpstamina`) — Forge 1.20.1

Мод выносливости для RP-сервера. Работает вместе с `rpperks` через атрибуты, события и API, но от него не зависит.

**Статус: v0.1.0, код написан без возможности скомпилировать (в среде разработки не было доступа к Maven).**
Первая сборка может выдать несколько ошибок компиляции из-за расхождений в именах методов Forge/маппингов — присылай вывод `gradlew build`, поправлю.

## Сборка

Нужна Java 17.

```
./gradlew build          # jar: build/libs/rpstamina-0.1.0.jar
./gradlew runClient      # тестовый клиент
./gradlew runServer      # тестовый сервер
```

Gradle wrapper — 8.1.1 (под ForgeGradle 6 / Forge 47.3.0). Если в `rpperks` у тебя другая версия Forge — поменяй `forge_version` в `gradle.properties`.
Мод нужен **и на клиенте, и на сервере** (сервер считает механику, клиент рисует полоску и снимает ванильный лимит бега).

## Что делает

- Полоска выносливости над шкалой опыта. Положение/размер: `config/rpstamina-client.toml` или прямо в игре — команда **`/staminahud`** (перетаскивание мышью, колесо — ширина, Shift+колесо — высота, кнопка смены якоря).
- Траты (все значения в конфиге): бег, прыжок, прыжок в беге, плавание, быстрое плавание, подъём по лестнице, добыча (за каждый тик и за окончательное разрушение, с учётом твёрдости и датапака `blocks`), удар в ближнем бою, размахи (первый за 5 секунд бесплатный, дальше платные с ростом цены), лук/арбалет/трезубец (датапак `use_costs`), щит (за удержание и за заблокированный урон).
- Восстановление: пауза после трат (короче — после обычной, длиннее — после падения в ноль) → скорость плавно нарастает до целевой, а падает мгновенно. Целевая скорость: ходьба < стоя < стоя+присев < сидя на транспорте < сон в кровати.
- Ноль выносливости: замедление на время, бег запрещён до порога (`resume_fraction`), медленнее добыча и слабее удар в ближнем бою.
- Голод: ванильный запрет бега при голоде ≤ 6 снят; действия больше не тратят ванильное насыщение; вместо этого насыщение/голод тратит **любое восстановление** — естественное и от предметов, по фактически восстановленному (`regen_costs_food`, `regen_food_cost_per_100`). Обе части отключаются в конфиге (`disable_vanilla_action_exhaustion`, `regen_costs_food`): при обоих `false` голод работает как в ваниле. Есть насыщение — бонус к восстановлению, мало голода — штраф.
- Вес брони: надбавка к расходу на движение `1 + clamp((вес − 5) × 0.02, 0, cap) × armor_burden`. В конфиге только вкл/выкл и потолок.
- Восстанавливающие предметы (датапак `consumables`): мгновенная часть (растягивается на 10 сек), пассивная регенерация, длительность, группа толерантности, необязательные откат-кулдаун и «отходняк» (`crash`).

## Данные (датапак и папка `config/rpstamina_custom`)

Данные по умолчанию лежат в моде: `data/rpstamina/rpstamina/<категория>/*.json`. Категории: `consumables`, `groups`, `use_costs`, `weapons`, `blocks`.

- Любой датапак может добавлять/перекрывать записи (`data/<ns>/rpstamina/<категория>/<имя>.json`), работает `/reload`.
- Отдельная папка **`config/rpstamina_custom/`** создаётся автоматически при первом запуске (с README и примером). Файлы оттуда перекрывают одноимённые записи мода и добавляют новые. Включать датапак не нужно.
- `/stamina export_defaults` — выложить копии данных по умолчанию в эту папку (существующие файлы не трогает).
- `/stamina reload` — перечитать папку без перезапуска.

Формат описан в `README.txt` внутри `rpstamina_custom`. Пример записи (вода):

```json
{
  "item": "minecraft:potion",
  "nbt": { "Potion": "minecraft:water" },
  "instant": 120, "instant_ticks": 200,
  "passive_per_tick": 0.03, "duration_ticks": 400,
  "group": "water"
}
```

Толерантность: у группы (`groups/<имя>.json`) есть значение T; каждое употребление добавляет `gain` (до `max`), эффективность (и мгновенной, и пассивной части) = `1 / (1 + T)`, T сам спадает на `decay_per_tick`. Откат «отходняк» — опциональный блок `crash`; у воды его нет.

Огнестрел и другие моды: мод трогает только предметы, явно перечисленные в `use_costs`, и считает «оружием» только предметы с атрибутом урона (или записанные в `weapons`). Клики предметами без атрибута урона размахами не считаются. Если какой-то модовый предмет нужно исключить — `weapons/*.json` с `"ignore": true`.

## Интеграция с rpperks

Атрибуты (вешать модификаторами на игрока):

| id | по умолчанию | назначение |
|---|---|---|
| `rpstamina:max_stamina` | 1000 (из конфига) | максимум выносливости |
| `rpstamina:regen_multiplier` | 1.0 | множитель восстановления |
| `rpstamina:cost_multiplier` | 1.0 | общий множитель расхода (0 = ничего не тратится) |
| `rpstamina:move_cost_multiplier` | 1.0 | расход на бег, прыжки, лестницы |
| `rpstamina:swim_cost_multiplier` | 1.0 | расход на плавание |
| `rpstamina:mine_cost_multiplier` | 1.0 | расход на добычу блоков |
| `rpstamina:melee_cost_multiplier` | 1.0 | расход на удары и размахи в ближнем бою |
| `rpstamina:armor_burden` | 1.0 | влияние веса брони на расход движения (0 = броня не мешает) |

Итоговый расход = цена действия × `cost_multiplier` × множитель категории × (вес брони, только для движения).
Если установлен `rpperks`, базу `max_stamina` задаёт его `[baseline]`, а `base_max_stamina` из конфига `rpstamina` игнорируется.
Без `rpperks` база ставится из конфига при входе, респавне и перезагрузке конфига (по событиям, не по таймеру).

```java
// пример «Атлета»: -20% расхода, +30% восстановления
var cost = player.getAttribute(ForgeRegistries.ATTRIBUTES.getValue(new ResourceLocation("rpstamina", "cost_multiplier")));
cost.addTransientModifier(new AttributeModifier(UUID, "rpperks athlete", -0.2, AttributeModifier.Operation.MULTIPLY_TOTAL));
```

События (шина Forge, отменяемые, значение можно менять): `StaminaConsumeEvent` (источник: `rpstamina:sprint`, `jump`, `sprint_jump`, `swim`, `swim_sprint`, `climb`, `mine_tick`, `mine_break`, `melee_hit`, `swing`, `item_use`, `shield_hold`, `shield_block`) и `StaminaRegenEvent`.

API: `faygolover.rpstamina.api.StaminaAPI` — `get`, `getMax`, `isExhausted`, `consume`, `add`, `set`. Подключать мягко (`ModList.get().isLoaded("rpstamina")`).

Что нужно поправить в `rpperks`: убрать атрибут `PARCOOL_STAMINA_RECOVERY` (Солнечная батарейка и т.п.) и перевесить на `rpstamina:regen_multiplier`/`max_stamina`. Сам `rpperks` я не менял.

## Команды (права оператора)

`/stamina get [игрок]`, `set <игроки> <число>`, `add <игроки> <число>`, `refill [игроки]`, `reload`, `export_defaults`, `debug [игрок]`. Клиентская: `/staminahud`.

## Синхронизация и полоска

Сервер шлёт клиенту значение и скорость изменения за тик; между пакетами клиент сам продвигает полоску и интерполирует её по `partialTick`. Пакет отправляется только когда реальное значение разошлось с предсказанием клиента (разовая трата, смена скорости или состояния), плюс редкая подстройка. При беге и отдыхе пакетов почти нет. Край полоски рисуется дробной шириной, поэтому даже растянутая полоска движется плавно. Если заметите расхождения между полоской и `/stamina get`, пришлите описание — пороги в `StaminaManager` (`DEVIATION_LIMIT`, `RATE_TOLERANCE`, `HEARTBEAT_*`).

## Известные ограничения и то, что стоит проверить в первую очередь

1. **Ванильные траты насыщения** отключены не перехватом `causeFoodExhaustion`, а сравнением значения до/после тика игрока (без mixin). Побочный эффект: во время тика, где игрок одновременно лечится от еды, траты этого тика не гасятся. Нагрузка на сервер ничтожна (несколько операций с числами на игрока за тик). Атрибуты читаются напрямую (Minecraft сам кэширует их значение), вес брони пересчитывается только при смене экипировки. Точнее делается через mixin, но от него решено отказаться.
2. **Снятие лимита бега при голоде** — клиентский трюк: на время тика подменяется уровень голода (20 — можно бежать, 0 — нельзя, пока измотан). Проверить, что при голоде ≤ 6 бег работает, а при нуле стамины — нет.
3. **Учёт добычи по тикам** опирается на `PlayerEvent.BreakSpeed`, который на сервере вызывается каждый тик добычи. Проверить `/stamina debug` во время копания.
4. **Размах** определяется клиентом (клик «атаки» не по блоку) и пакетом уходит на сервер; без мода на клиенте размахи не считаются.
5. Конфиг механики — SERVER-тип, как в `rpperks`: лежит в `<мир>/serverconfig/rpstamina-server.toml`.
6. Пулы восстановления и пассивные эффекты предметов не сохраняются при выходе из игры (сохраняются стамина, состояние измотанности и толерантность).
7. Значения по умолчанию — стартовые прикидки, их нужно подкручивать на практике.
